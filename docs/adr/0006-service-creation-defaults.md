# 0006. 서비스 생성 기본값과 이름 규칙

- 상태: 대체됨(0027)
- 날짜: 2026-10-01
- 결정자: 김지민

## 배경
Railway 는 저장소만 고르면 서비스를 만든다. 생성 요청의 어떤 값을 생략할 수 있게 할지, 이름을 어떻게 제한할지 정해야 한다.

## 결정
- 필수 입력은 저장소(URL 또는 `owner/name`)뿐이다. 이름은 저장소 이름을 소문자·하이픈으로 바꾼 값, 브랜치는 저장소 기본 브랜치가 기본값이다.
- 지정한 브랜치는 GitHub 에 실제로 있는지 확인한다(없으면 `422`).
- `targetIds` 를 생략하면 등록된 **모든 타깃**에 배포한다("같은 이미지를 여러 타깃에" 컨셉). 빈 목록·없는 타깃은 `422`.
- 서비스 이름은 DNS 레이블 규칙(소문자·숫자·하이픈, 63자)이다. 이후 도메인(서브도메인)에 쓰이기 때문이다.
- 루트 디렉터리는 저장소 안 상대 경로로 정리하고 `..` 는 거부한다.
- 빌더는 코드 분석으로 확정하기 전까지 비워 둔다(확정 전 배포하지 않음).
- PATCH 는 보낸 필드만 바꾸고, 명시한 `null` 은 값을 비운다(이름·브랜치·자동배포·타깃은 비울 수 없음).

## 결과
- 사용자는 저장소만 골라도 서비스가 만들어진다.
- 기본값이 "모든 타깃"이라 타깃이 늘면 새 서비스의 배포 범위도 늘어난다. 이 기본값은 필요하면 바꾼다.
